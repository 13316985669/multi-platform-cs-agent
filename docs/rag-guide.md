# 知识库运营手册

RAG 是 AI 客服回答质量的根基。本手册面向运营同学，讲清楚「怎么喂知识，AI 才答得准」。

## 检索管线（了解原理才能养好知识）

```
用户问题 → 没有指代则用原句，否则查询改写 → 向量检索 + BM25 关键词 → RRF 融合 → Rerank 精排 → 没过阈值再放宽问法重检一次 → 仍没有则兜底后转人工
```

- **向量检索**：理解语义（「多少钱」能命中「价格 99 元」）
- **BM25**：精确匹配关键词（型号「X200 Pro」、货号不会丢）
- **Rerank**：精排取 Top3。接口空了或调用失败时退回混合检索结果；只有精排分低于阈值（默认 0.35）才判定「无命中」→ AI 承认不知道并转人工，**从源头防瞎编**

## FAQ 编写规范（召回率最高的知识形式）

FAQ 问答对会**整体作为一个 chunk** 索引，不拆散，精度最高。编写要点：

| 要点 | 好例子 | 坏例子 |
|---|---|---|
| 标题即主题 | 「产品价格」 | 「常见问题 1」 |
| 问题用用户口语 | 「这个多少钱」「包邮吗」 | 「请说明产品定价策略」 |
| 一个 FAQ 只讲一件事 | 价格一条、运费一条 | 价格运费售后全塞一条 |
| 答案给确定结论 | 「标准款 99 元，两件九折」 | 「价格视情况而定」 |
| 覆盖同义问法 | 问题里写「多少钱/什么价/怎么卖」 | 只写书面语 |

## 文档上传

支持 PDF / Word / Markdown / TXT（≤10MB）。系统自动：
1. 按章节标题、完整清单和空行切成语义块
2. 相邻块在完整句子处重叠约 15%
3. 没有标题的长段，在句子语义明显转折处切开

检索命中的是这些语义块本身。资料变更后，引用过该文档的回答缓存会失效。

**建议**：产品手册、政策文档直接上传；高频问题务必整理成 FAQ（比文档召回准得多）。

## 召回测试台（调优神器）

知识库页 →「召回测试台」，输入测试问题可看到：
- 改写后的查询（检查指代消解对不对）
- 每路召回结果与 Rerank 分数
- 是否过阈值（不过 = 实际接待中会转人工）

**调优建议**：
- 测试问题没召回 → 检查知识里有没有对应内容，补 FAQ
- 召回了但分数低 → 问题表述和知识表述差异大，改写 FAQ 的「问」更贴近用户口语
- 不该过的过了 → 调高阈值（`.env` 的 `RAG_RERANK_THRESHOLD`）

## 未命中问题闭环（最重要的日常运营）

AI 答不了的问题自动沉淀到「未命中问题」列表（按被问次数排序）：

1. 每天看一眼未命中列表
2. 高频问题点「转 FAQ」，补标准答案
3. 保存即自动索引，AI 立刻就会答了

这就是知识库越用越聪明的飞轮：**未命中 → 补知识 → 命中率提升 → 转人工率下降**。

## bad case 标记

工作台上客服发现 AI 答得不好，点消息下方的「标记不佳」。定期导出这些消息，对照当时的检索引用（消息可展开「参考了 N 条知识」）分析：
- 引用对了但答得差 → 改提示词
- 引用就错了 → 改知识库 / 调阈值

## 降级模式说明

未配置 Embedding API 时系统自动降级为纯 BM25 检索（测试台会显示黄色提示）。此时语义泛化能力弱，**FAQ 的「问」要尽量覆盖用户的多种问法**。配置硅基流动 `EMBEDDING_API_KEY`（有免费额度）后即恢复完整混合检索。
